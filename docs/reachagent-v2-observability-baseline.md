# ReachAgent V2 observability baseline

Baseline date: 15 September 2026 (Australia/Sydney)

Scope: isolated V2 application and `supabase-v2` only. This audit was completed before the Prompt 10 implementation. It distinguishes diagnostic evidence from operational state so the new layer does not become a second state machine.

## Baseline conclusions

The smallest useful addition is `workflow_runs` plus `workflow_steps`. Existing operational tables are not replaced. `activity_log` remains the one location for lead status-transition activity, `ai_request_logs` remains the one AI pricing/usage record, and provider-specific durable IDs remain in their operational tables. The new tables provide a bounded diagnostic spine joining those records.

Known pre-existing gaps include ad hoc stack traces in some legacy `activity_log` metadata, inconsistent provider request IDs outside Resend/Hostinger, and many agent logs without stable run IDs. Prompt 10 addresses new structured writes and the highest-value paths; it does not rewrite all historical logging.
